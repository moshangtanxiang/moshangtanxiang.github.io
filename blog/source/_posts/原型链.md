## 为什么需要原型 & 原型链？
JavaScript 是一门基于原型的面向对象编程语言，没有类（class）的原生概念（ES6 的 class 只是语法糖）。
在 JS 中，如果我们通过构造函数创建多个实例对象：
```
// 构造函数
function Person(name, age) {
  this.name = name;
  this.age = age;
  this.sayHi = function(){
    console.log('你好，我是'+this.name)
  }
}
// 创建多个实例
const p1 = new Person('张三', 20);
const p2 = new Person('李四', 22);
```
此时会出现一个致命问题：p1和p2身上都有一个独立的 sayHi 方法，每创建一个实例，就会在内存中开辟一块新空间存储相同的方法，造成了极大的内存浪费。
原型的诞生，就是为了解决这个问题：把公共的属性和方法抽离出来，让所有实例对象共享这一份内容，而不是每个实例都复制一份。
✅ **核心目的：数据共享、节省内存**

## 概念
* JS中万物皆对象
* 函数本质也是对象
    - 所有函数自带一个属性：prototype（显示原型），该属性指向该函数的原型对象
    - prototype 的值是一个普通的对象（「函数的原型对象」）
    - 这个原型对象上，默认自带一个属性：constructor，指向当前这个函数本身
* 每个对象都有一个属性：\_\_proto\_\_（隐式原型），该属性指向该对象的构造函数的原型对象
* **\_\_proto\_\_是所有对象（包含实例）的实例属性**
* **\_\_proto\_\_是建立实例对象和构造函数原型对象之间的联系，是原型链的核心链路桥梁，也是实现「属性查找」的核心**
* **prototype是构造函数才有的专属属性**

## 原型链 核心定义&本质&查找规则
### 核心定义
__当访问一个对象的属性或方法时，如果这个对象本身没有该属性或方法，那么会通过对象的\_\_proto\_\_去查找它的【构造函数的原型对象】；如果原型对象上也没有，那么会通过原型对象的\_\_proto\_\_向上查找，直到找到该属性或方法或者原型对象为 null 为止（Object.prototype.\_\_proto\_\_=null）。__
**这个通过 \_\_proto\_\_ 串联起来的、层层向上查找的对象链路，就叫做 原型链。**

### 本质
原型链的本质：__对象与对象之间的继承关系链路__
原型链的链路载体：**所有对象的 \_\_proto\_\_ 属性**

### 查找规则
__访问规则：先找自己，再找原型，找不到就向上找，直到顶层__
1. 先从对象本身查找，如果对象本身有该属性或方法，则返回该属性或方法;
2. 如果对象本身没有该属性或方法，则通过 \_\_proto\_\_ 链路向上查找(原型对象);
3. 如果原型对象上也没有，那么会通过原型对象的 \_\_proto\_\_ 继续向上查找；
4. 知道找到该属性或方法，或者Object.prototype(原型链顶端)
5. 如果Object.prototype上也没有该属性或方法，则返回 undefined。
6. 即 Object.prototype.\_\_proto\_\_=null
7. __注意__：这个规则是「只读」的，__属性赋值不会走原型链，赋值只会给「对象自身」添加属性__。
```
function Person() {}
Person.prototype.age = 18;
const p1 = new Person();

// 给p1赋值age，只会给p1自身添加age属性，不会修改原型上的age
p1.age = 20;
console.log(p1.age); // 20 （自身属性）
console.log(Person.prototype.age); // 18 （原型属性不变）
console.log(p1.hasOwnProperty('age')); // true 确认是自身属性
console.log(p1.name); // undefined
```

## 常用公式
```
// 公式1：实例的隐式原型  ===  构造函数的显式原型
实例._\_\_proto\_\__ === 构造函数.prototype 

// 公式2：所有函数的显式原型 都是一个对象，这个对象的构造函数是 Object
构造函数.prototype._\_\_proto\_\__ === Object.prototype

// 公式3：所有函数都是 Function 的实例
任意函数._\_\_proto\_\__ === Function.prototype

// 公式4：Function的原型 也是 Object的实例
Function.prototype._\_\_proto\_\__ === Object.prototype

// 公式5：原型链的顶端闭环
Object.prototype._\_\_proto\_\__ === null

// 公式6：Object/Function 自身也是函数，互相指向
Function._\_\_proto\_\__ === Function.prototype
Object._\_\_proto\_\__ === Function.prototype
```

## prototype 和 \_\_proto\_\_ 的区别
* 所属不同：prototype 属于函数，\_\_proto\_\_ 属于对象
* 作用不同：prototype 用于挂载公共属性方法，\_\_proto\_\_ 用于建立实例和原型的联系，实现查找
* 指向不同：prototype 指向「函数的原型对象」，\_\_proto\_\_ 指向「创建对象的构造函数的 prototype」

## 原型链查找会查找原型链上的所有属性吗？
不会！__原型链查找只会查找「可枚举属性」__，如果属性的 enumerable 为 false（不可枚举），则不会被遍历到（比如 Object.prototype 上的 toString 就是不可枚举的）

## 测试一下
```
var F = function(){}
Object.prototype.a=function(){}
Function.prototype.b=function(){}
var f = new F()
console.log(f.a, f.b, F.a, F.b) // 打印什么？
```

F 是一个函数，当我们执行 var f = new F() 时：
    _ f.\_\_proto\_\_ 指向 F.prototype（这是一个普通对象）
    _ F.prototype 是一个普通对象，它的 \_\_proto\_\_ 指向 Object.prototype
    _ F.\_\_proto\_\_ 指向 Function.prototype（因为 F 是函数）
所以原型链是这样的：
    __实例 f 的原型链：f.\_\_proto\_\_ → F.prototype → Object.prototype__
    __函数 F 的原型链：F.\_\_proto\_\_ → Function.prototype → Object.prototype__

1. f.a → function(){}
    - f 是 new F() 创建的实例
    - f 的原型链：f.\_\_proto\_\_ → F.prototype → Object.prototype
    - Object.prototype.a 存在，所以 f.a 可以访问到
2. f.b → undefined
    - f 是对象实例，不是函数
    - f 的原型链：f.\_\_proto\_\_ → F.prototype → Object.prototype
    - Function.prototype.b 不在 f 的原型链上，所以 f.b 是 undefined
3. F.a  → function(){}
    - F 是函数对象
    - F 的原型链：F.\_\_proto\_\_ → Function.prototype → Object.prototype
    - Object.prototype.a 存在，所以 F.a 可以访问到
4. F.b → function(){}
    - F 是函数
    - F 的原型链：F.\_\_proto\_\_ → Function.prototype
    - Function.prototype.b 存在，所以 F.b 可以访问到
